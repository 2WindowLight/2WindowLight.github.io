## **키워드 분석**

- **"1분마다 데이터 수신"** → **실시간 스트리밍** 필요 (Kinesis Data Streams/Firehose).
- **"실시간 분석"** → **Kinesis Data Analytics** 또는 **Lambda** 활용.
- **"데이터 레이크(S3)로 수집"** → **Kinesis Data Firehose**가 S3와 직접 통합됨.

------

## **서비스별 특징 비교**

| **서비스**                 | **주요 기능**                                         | **적합 시나리오**                         |
| :------------------------- | :---------------------------------------------------- | :---------------------------------------- |
| **Kinesis Data Streams**   | 실시간 데이터 수집 & 임시 저장 (사용자 관리)          | 초저지연 처리, 사용자 정의 분석 필요 시   |
| **Kinesis Data Firehose**  | 데이터를 S3/Redshift 등에 **자동 전송** (완전 관리형) | 데이터 변환 없이 바로 저장할 때           |
| **Kinesis Data Analytics** | SQL/플링크 기반 **실시간 분석**                       | 복잡한 스트림 분석 (예: 이상 감지)        |
| **AWS Lambda**             | 이벤트 기반 데이터 처리                               | 간단한 실시간 변환 (예: JSON 파싱)        |
| **API Gateway**            | REST API 생성                                         | HTTP 기반 데이터 수집 (실시간 스트리밍 X) |

------

### **문제 풀이 Flow**

1. **데이터 수집**
   - **Kinesis Data Streams** or **Kinesis Data Firehose** 선택.
   - **Firehose**는 S3 자동 저장, **Streams**는 추가 처리 필요.
2. **실시간 분석**
   - **Kinesis Data Analytics** (SQL 분석) vs **Lambda** (커스텀 코드).
   - 복잡한 분석 → **Data Analytics**, 단순 처리 → **Lambda**.
3. **데이터 레이크 저장**
   - **Kinesis Data Firehose**는 S3로 바로 저장.
   - **Kinesis Data Streams + Lambda**는 별도 저장 로직 필요.

------

### **옵션별 검토**

- **(A) Kinesis Data Streams + Lambda**
  - **장점**: 초저지연 처리.
  - **단점**: S3 저장을 위해 Lambda 추가 구성 필요.
- **(B) AWS Glue + Kinesis Data Analytics**
  - **Glue**는 배치 ETL용 → **실시간 부적합**.
- **(C) Kinesis Data Firehose + Data Analytics**
  - **Firehose**로 S3 자동 저장 + **Data Analytics**로 실시간 분석 → **최적**.
- **(D) API Gateway + Lambda**
  - **API Gateway**는 초고빈도 스트리밍에 비효율적 → **비추천**.

------

### **주의사항**

- **Kinesis Data Streams** vs **Firehose**:
  - **Firehose**는 별도 저장 로직 없이 S3/Redshift와 통합되지만, **버퍼링 지연** (최대 1분) 발생.
  - **Data Streams**는 초저지연이지만, S3 저장을 위해 Lambda/Firehose 추가 필요
