### **핵심 비교표**

| **서비스**            | **용도**                             | **특징**                                      | **비용 효율성**                | **적합 시나리오**               |
| :-------------------- | :----------------------------------- | :-------------------------------------------- | :----------------------------- | :------------------------------ |
| **EBS**               | 단일 EC2 인스턴스 전용 스토리지      | - 단일 AZ 종속 - 볼륨 유형 선택 (gp3, io2 등) | 중간 (사용량 기반)             | OS 디스크, 단일 AZ 데이터베이스 |
| **EFS**               | 다중 EC2 인스턴스 공유 스토리지      | - 다중 AZ 지원 - NFS 프로토콜                 | 높음 (공유 스토리지 필요 시)   | 웹 서버 로그, 공유 파일 시스템  |
| **S3**                | 정적 파일/대용량 데이터 저장         | - 객체 스토리지 - 버저닝/암호화 지원          | 매우 높음 (저장 비용 최저)     | 이미지, 백업, 정적 웹 콘텐츠    |
| **FSx**               | 특화된 파일 시스템 (Windows, Lustre) | - 완전 관리형 - 다중 AZ 지원                  | 중간~높음 (특수 용도에 최적화) | Windows 클러스터, 고성능 컴퓨팅 |
| **RDS**               | 관리형 관계형 데이터베이스           | - MySQL, PostgreSQL 등 지원 - 다중 AZ 복제    | 중간 (Aurora보다 저렴)         | 일반적인 웹 애플리케이션 백엔드 |
| **Aurora**            | 고성능 관계형 데이터베이스           | - MySQL/PostgreSQL 호환 - 다중 AZ 자동 복제   | 중간~높음 (성능 대비 효율적)   | 확장성 있는 고성능 애플리케이션 |
| **Aurora Serverless** | 서버리스 관계형 데이터베이스         | - 트래픽 기반 자동 확장 - 운영 오버헤드 없음  | 높음 (변동 트래픽 시)          | 변동적 트래픽, 비용 효율성 요구 |

------

### **문제 풀이 전략**

1. **관계형 데이터베이스 선택 기준**
   - **RDS**: 다양한 엔진 지원 + 기본적인 고가용성 (Multi-AZ) 필요 시.
   - **Aurora**: 고성능 + 자동 복제 + 글로벌 확장 필요 시.
   - **Aurora Serverless**: 트래픽 변동이 심한 서버리스 아키텍처 필요 시.
2. **비용 효율성 우선순위**
   - **최저 비용**: S3 > EBS gp3 > RDS (범용 인스턴스).
   - **고성능 대비 효율**: Aurora > RDS (Provisioned IOPS).
   - **서버리스**: Aurora Serverless (사용량 기반).
3. **스토리지 선택 기준**
   - **공유 스토리지**: EFS (다중 AZ) > FSx (Windows/Lustre).
   - **단일 인스턴스**: EBS (단일 AZ).
   - **대용량 정적 데이터**: S3.

------

### **주의할 키워드**

- **"관계형 데이터베이스"** → RDS, Aurora.
- **"서버리스"** → Aurora Serverless, Lambda.
- **"다중 AZ"** → Aurora, RDS Multi-AZ, EFS.
- **"고성능"** → Aurora, EBS io2, FSx Lustre.
- **"최저 비용"** → S3, EBS gp3.
