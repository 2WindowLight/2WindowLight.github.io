## **주요 연결 서비스 비교**

| **서비스**           | **사용 사례**                        | **보안**                          | **비용/복잡도**                | **주의사항**                               |
| :------------------- | :----------------------------------- | :-------------------------------- | :----------------------------- | :----------------------------------------- |
| **AWS PrivateLink**  | AWS 내부/타사 서비스와 비공개 연결   | 인터넷 미경유 + 엔드포인트 암호화 | 중간 (서비스 제공자 협력 필요) | 타사가 VPC 엔드포인트 서비스를 제공해야 함 |
| **VPC 피어링**       | 동일 리전 내 VPC 간 통신             | 비공개 연결 (인터넷 미경유)       | 저렴                           | CIDR 범위 중복 불가, 트랜짓 라우팅 미지원  |
| **Site-to-Site VPN** | 온프레미스-VPC 연결 (인터넷 경유)    | IPsec 암호화                      | 저렴 (암호화 오버헤드)         | 대역폭 제한, 지연 시간 변동 가능           |
| **Direct Connect**   | 온프레미스-VPC 전용선 연결           | 물리적 보안 (전용 회선)           | 고비용 (설치 시간 소요)        | 데이터 센터와 AWS 간 직접 연결             |
| **Transit Gateway**  | 다중 VPC/온프레미스 중앙 집중식 연결 | 라우팅 제어 + 암호화 옵션         | 중간 (허브-스포크 모델)        | 복잡한 라우팅 테이블 관리 필요             |

## **시험 문제 핵심 키워드 & 매핑 서비스**

- **"비공개 연결"**
  → **AWS PrivateLink** (타사 서비스가 AWS 호스팅일 때)
  → **VPC 피어링** (동일 리전 내 VPC 간)
- **"최소 인터넷 노출"**
  → **PrivateLink**, **Direct Connect**, **VPC 피어링**
- **"크로스 리전 통신"**
  → **Transit Gateway**, **VPC 피어링 (리전 간)**
- **"타사 서비스 통합"**
  → **PrivateLink** (AWS 호스팅 타사) / **VPN** (비-AWS 호스팅 타사)
- **"고가용성 연결"**
  → **Direct Connect + VPN** (장애 조치용)

## **서비스별 상세 설명**

#### **(1) AWS PrivateLink** - 인터넷을 거치지 않고 **VPC 엔드포인트**를 통해 서비스에 직접 접근, 외부 서비스(온프레미스 등) 안전한 전용회선 통신

#### **(2) VPC 피어링** - 동일/다른 리전의 VPC 간 **비공개 연결**, 인터넷 없이 라우팅 (동일 리전 피어링을 권장)

#### **(3) Site-to-Site VPN** - **IPsec 터널**을 통해 인터넷으로 연결 , Virtual Private Gateway (VGW)** 필요.

#### **(4) Direct Connect** - 전용 회선**을 통한 연결로 지연 시간/대역폭 보장.

#### **(5) Transit Gateway** - 중앙 허브를 통해 **다중 VPC/온프레미스 연결 관리**.

------

### **시험 문제 풀이 전략**

1. **문제 키워드 선별**:
   - "비공개", "암호화", "최소 인터넷 노출" → **PrivateLink** 또는 **Direct Connect**.
   - "다중 VPC", "중앙 관리" → **Transit Gateway**.
   - "동일 리전" → **VPC 피어링**.
2. **보안 계층 확인**:
   - **네트워크 계층 (L3)**: VPN, Direct Connect.
   - **애플리케이션 계층 (L7)**: HTTPS, KMS.
3. **트래픽 경로 분석**:
   - **인터넷 경유 여부 → VPN vs PrivateLink/Direct Connect.**
   - **대역폭/지연 시간 요구사항 → Direct Connect 우선.**
   - **"타사 서비스 비공개 접근"** → **PrivateLink**.
4. **함정 주의**:
   - **VPC 피어링**은 트랜짓 라우팅을 지원하지 않음 → Transit Gateway 필요.
   - **PrivateLink**는 타사가 엔드포인트 서비스를 제공해야 가능

------

### **주의할 함정**

1. **Interface 엔드포인트 오답 유도**:
   - S3는 **Gateway 엔드포인트**만 지원 → Interface 엔드포인트 선택 시 오답.
2. **NAT Gateway/인터넷 게이트웨이 사용**:
   - 문제에서 "인터넷 없이"를 강조하면 **NAT Gateway는 오답** (인터넷 사용).
3. **S3 Transfer Acceleration**:
   - 인터넷을 통한 전송 가속화 → **비공개 접근 요구사항과 무관**.
