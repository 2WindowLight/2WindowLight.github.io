### **데이터 분석 서비스 종합 비교**

| **서비스**             | **주요 목적**                                                | **보안**                                | **비용/복잡도**                | **주의사항**               |
| :--------------------- | :----------------------------------------------------------- | :-------------------------------------- | :----------------------------- | :------------------------- |
| **Amazon Athena**      | S3에 저장된 데이터를 분석하기 위한 **서버리스** SQL 쿼리 서비스 | IAM 정책 + S3 암호화                    | 쿼리당 데이터 스캔량           | 대규모 데이터는 비용 ↑     |
| **Amazon Redshift**    | **데이터 웨어하우징** (컬럼 기반)                            | VPC 격리, 암호화, IAM                   | 노드 유형 + 사용 시간          | 데이터 로드 필요           |
| **Amazon EMR**         | **빅데이터 처리** (Hadoop/Spark)                             | 보안 그룹, IAM, Kerberos 통합           | 인스턴스 + 스토리지 비용       | 클러스터 관리 복잡성       |
| **AWS Glue**           | **서버리스 ETL** (데이터 변환)                               | IAM, 데이터 암호화, Lake Formation 통합 | 작업 실행 시간 + DPU           | 간단한 ETL에 최적화        |
| **AWS Lake Formation** | **데이터 레이크 통합 관리**                                  | 중앙 권한 제어, 암호화, 감사 로깅       | 저장소/처리량 별 추가 요금     | S3 기반 데이터 레이크 필수 |
| **Amazon OpenSearch**  | **로그/ 오픈 소스 검색 분석** (실시간)                       | VPC 격리, IAM, 암호화                   | 인스턴스 유형 + 스토리지       | Elasticsearch 호환         |
| **Amazon Kinesis**     | **실시간 데이터 스트리밍**                                   | IAM, 암호화, VPC 엔드포인트             | 샤드/사용 시간 + 데이터 처리량 | 초고속 데이터 수집 전용    |
| **AWS Data Pipeline**  | **데이터 워크플로 오케스트레이션**                           | IAM, 암호화                             | 파이프라인 실행 횟수           | 단순 워크플로에 적합       |
| **Amazon QuickSight**  | **BI 시각화**                                                | IAM, 행 수준 보안 (RLS)                 | 사용자 세션/스토리지           | Redshift/Athena와 통합     |
| **AWS DataSync**       | **대량 데이터 이동** (온프레미스 ↔ AWS)                      | TLS 암호화, IAM                         | 데이터 전송량                  | NAS/S3/EFS/FSx 간 전용     |

### **키워드별 문제 풀이 전략**

#### **(1) "ETL이 필요한 경우"**

- **AWS Glue**: 서버리스, 자동 스케일링, 데이터 카탈로그 통합.
- **Amazon EMR**: 복잡한 Spark/Hadoop 작업, 대규모 배치 처리.

#### **(2) "실시간 분석"**

- **Amazon Kinesis**: 초당 수백만 이벤트 처리 (Data Streams).
- **Amazon OpenSearch**: 로그 검색 및 시각화 (Kibana 통합).

#### **(3) "데이터 웨어하우징"**

- **Amazon Redshift**: 컬럼 기반 저장, 복잡한 쿼리 최적화.
- **Amazon Athena**: S3 데이터 직접 쿼리 (Ad-hoc 분석).

#### **(4) "데이터 레이크 관리"**

- **AWS Lake Formation**: 데이터 카탈로그, 크로스 계정 접근 제어.
- **Amazon S3**: 원시 데이터 저장 (Lake Formation과 함께 사용).

------

### **주의할 함정**

- **Athena vs Redshift**
  - **Athena**: S3 데이터 직접 쿼리 (스캔 비용).
  - **Redshift**: 데이터를 먼저 로드해야 함 (저장 비용).
- **Glue vs EMR**
  - **Glue**: 서버리스 ETL (간단한 변환).
  - **EMR**: 사용자 정의 빅데이터 처리 (복잡한 작업).
- **OpenSearch vs CloudWatch Logs**
  - **OpenSearch**: 풀텍스트 검색, 사용자 정의 대시보드.
  - **CloudWatch Logs**: 기본 모니터링 + Insights.

------

### **ETL (Extract, Transform, Load) 간단 정리**

- **Extract**: 데이터 소스 (S3, RDS) → **추출**.
- **Transform**: 데이터 정제 (필터링, 집계) → **변환**.
- **Load**: 목적지 (Redshift, S3) → **적재**.

------

###  **요약**

- **Athena**: S3 데이터 즉시 분석.
- **Redshift**: 대규모 BI 분석.
- **Glue**: 서버리스 ETL.
- **OpenSearch**: 실시간 로그 검색.
- **Lake Formation**: 데이터 레이크 통합 관리.

**시험 Tip**:

- **"서버리스"** → Athena, Glue, Lambda.
- **"실시간"** → Kinesis, OpenSearch.
- **"중앙 관리"** → Lake Formation.
